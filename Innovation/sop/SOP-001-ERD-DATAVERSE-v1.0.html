01
Objective & Scope

This procedure establishes the standardized steps that the development team must follow to generate the Entity Relationship Diagram (ERD) for any solution built on Microsoft Dataverse, ensuring a visually consistent, technically accurate result ready to be included in the project's technical documentation.

ℹ️
Scope Applies to all custom solutions built on Microsoft Dataverse (Power Platform). Does not apply to standard Dynamics 365 entities that have not been modified within the solution.
02
Prerequisites
RequirementDetailsStatus
XrmToolBox Version 1.2021 or higher installed on the developer's machine Required
Dataverse Credentials Access with System Administrator or System Customizer role in the target environment Required
ERD Creator Plugin Entity Relation Diagram Creator, available in the XrmToolBox Plugin Store Required
Technical Documentation Solution architecture document identifying entities and their relationships Required
Claude AI Access Account on claude.ai for generating the visual ERD as an HTML file Required
03
Connecting to Dataverse with XrmToolBox
1
Open XrmToolBox

Launch the XrmToolBox application from the local machine. On the start screen, click New Connection or select a previously saved connection.

2
Configure the connection

Select the authentication type that matches the target environment (Office 365 / Azure AD). Enter the Dataverse environment URL in the following format:

https://<environment-name>.crm.dynamics.com

Enter the credentials and click Login. Once the connection is established, XrmToolBox will display the organization name in the top bar.

3
Verify the connection

Confirm that the connected environment is correct (DEV / QA / PROD) before proceeding. Always work on the development environment unless the procedure explicitly states otherwise.

⚠️
Environment Caution Always verify that the connection points to the correct environment before starting any operation. An accidental operation on PROD can have unintended consequences.
04
Installing the ERD Creator Plugin
1
Access the Plugin Store

In the XrmToolBox menu bar, navigate to Tools → Plugin Store.

2
Search and install the plugin

In the Plugin Store search bar, type:

Entity Relation Diagram Creator

Select the plugin from the results and click Install. Wait for the download and installation to complete. Restart XrmToolBox if prompted.

3
Open the plugin

On the XrmToolBox home screen, find Entity Relation Diagram Creator in the tools list and double-click to open it. Ensure the active connection is correct before proceeding.

05
Selecting & Filtering Entities
1
Load the solution

In the plugin panel, click Load Solutions. A list of all available solutions in the environment will appear. Select the solution corresponding to the project.

2
Load the solution's entities

Once the solution is selected, click Load Entities. The plugin will list all entities (tables) belonging to the selected solution.

3
Identify and select related entities

Based on the solution's technical architecture documentation, identify which entities have relationships with each other and which are auxiliary or configuration tables.

Select only the related entities that form part of the core data model. Exclude configuration tables, process flags, and technical utilities (see Section 6).

4
Configure rendering options

In the Diagram rendering options panel, the following standard configuration is recommended:

OptionRecommended Value
Number of entities per row5 (adjust based on entity count)
Fields to showCustom fields from all publishers
Show data types in entities✅ Enabled
Show Friendly names in entities✅ Enabled
Show fieldnames in relationships✅ Enabled
Show name of many-to-many relationship✅ Enabled
Show collapsed entities⬜ Disabled
Hide unpublished customizations⬜ Disabled
5
Generate the diagram

Click the Create Entity Relation Diagram button. The plugin will process the selected entities and render the diagram in the main view.

⚠️
Rendering Error If the plugin throws the error System.ArgumentOutOfRangeException: Index and length must refer to a location within the string, review Section 6 to identify and exclude the problematic tables. Then click Continue to attempt to proceed, or restart the process without the conflicting entities.
06
Excluded Tables — Technical Restriction
🚫
Root cause of the error Certain configuration and utility tables in Dataverse contain fields whose metadata presents empty strings ("") or special characters in properties such as the logical name or display name. The Entity Relation Diagram Creator plugin processes these strings using a String.Substring(startIndex, length) operation that assumes a minimum string length. When it encounters a string shorter than expected — or an empty one — it throws a System.ArgumentOutOfRangeException, interrupting the entire diagram rendering process.

The following tables must be mandatorily excluded when generating the ERD. They do not represent entities of the core data model — they are technical support, environment configuration, and process flag tables:

Table (Logical Name)Display NameReason for ExclusionStatus
cf_action Action System action configuration table. Metadata contains empty fields. Exclude
cf_admin Admin Administrative configuration table. Not part of the relational model. Exclude
cf_developer Developer Internal development-use table. Has no relationships with the core model. Exclude
cf_override Override Configuration override table. Causes metadata conflict in the plugin. Exclude
cf_processphaseflags Process Phase Flags Process phase control flags. Incomplete metadata that breaks rendering. Exclude
✅
Note If future projects identify additional tables that trigger the same error, they must be documented in this section and added to the permanent exclusion list of this procedure.
07
Exporting the Diagram
1
Export to Draw.IO

Once the diagram is generated in XrmToolBox, click the Export to Draw.IO button in the plugin toolbar. A file with the .drawio or .xml extension will be downloaded.

2
Rename the file extension

Locate the downloaded file and rename its extension from .drawio (or .xml) to .txt.

# Rename example: Before: Unified_CSR_Portal.drawio After: Unified_CSR_Portal.txt

This step is necessary because Claude AI accepts plain text files. The file content is valid XML and is not modified — only the extension changes.

ℹ️
Naming Convention Name the file following the standard: <SolutionName>_v<version>.txt — for example: Unified_CSR_Portal_v2.txt
08
Generating the Visual ERD with Claude AI
1
Access Claude AI

Go to claude.ai using the team credentials. Start a new conversation.

2
Attach the .txt file

Click the attach file icon (📎) in the Claude text box and select the .txt file generated in the previous step.

3
Use the standard prompt

Together with the attached file, send the following standardized prompt (see Section 9 for a reference of the expected output format):

📋 Standard Prompt — copy and paste as-is

I am attaching a .txt file exported from XrmToolBox containing the ERD of a Dataverse solution. Please create an interactive HTML ERD diagram following the team's visual standard: entities with fields differentiated by PK (gold) and FK (blue), relationships with Crow's Foot notation (single vertical bar on the "1" side and crow's foot on the "N" side) plus "1" and "N" labels at each end, a pan & zoom canvas with draggable entities, a search bar, minimap, and dark theme. The result must be a single self-contained HTML file, ready to download.

4
Download the generated HTML

Claude will process the file and generate the ERD HTML. Click the download button on the generated artifact. Save the file using the standard name:

<SolutionName>_ERD.html
09
ERD Visual Standard

Every ERD generated by the team must comply with the following visual and functional criteria. This standard is kept consistent across projects to facilitate cross-reading of technical documentation.

ElementSpecification
Output format Single self-contained HTML file (no external dependencies except Google Fonts)
Theme Dark — background #0f1117, cards #1a1d27
Typography IBM Plex Sans (UI) + IBM Plex Mono (code and data types)
Entity colors Each functional domain is assigned a distinctive color by the developer
PK fields Gold badge (#fbbf24) with "PK" label to the left of the field name
FK fields Blue badge (#60a5fa) with "FK" label to the left of the field name
Relationship notation Crow's Foot: single vertical bar on the "1" end, crow's foot on the "N" end
Cardinality labels "1" and "N" text floating at each end of the relationship line
Interactivity Pan, zoom (mouse wheel), entity dragging, search, relationship highlight on hover
Minimap Thumbnail view in the bottom-right corner for navigation
10
Final Considerations
📁
ERD Versioning The HTML ERD file must be versioned alongside the project documentation. Use the following naming convention: <Solution>_ERD_v1.0.html
🔄
ERD Updates The ERD must be regenerated every time relationships between entities are added, removed, or modified in the solution. An ERD from a previous version is not considered valid documentation for the current state of the solution.
📌
New Problematic Tables If additional tables that trigger the ArgumentOutOfRangeException error are identified during the process, report them to the technical lead to update the exclusion list in Section 6 of this procedure.
Documentation Storage & Version Control Platform

The choice of platform for storing and versioning ERD files and technical documentation is at the discretion of the Operations team. However, based on the team's existing toolset and typical enterprise patterns, two platforms are recommended: Microsoft SharePoint and Atlassian Confluence. Below is a structured comparison to support an informed decision.

🔷 Microsoft SharePoint
✔ Advantages
Native integration with Microsoft 365, Teams, and Dataverse — no additional licensing in most enterprise plans
Built-in version history for all documents, including HTML files, with restore capability
Granular permission management aligned with existing Azure Active Directory groups
HTML files can be previewed and served directly from SharePoint as web pages
Familiar to most enterprise users — lower adoption friction
✖ Disadvantages
Not designed as a documentation wiki — organizing structured technical docs requires manual folder conventions
No native inline diagramming or rich technical documentation features (no code blocks, tables, etc.)
Search across documents can be inconsistent for technical content
✦ Best for
Teams already on Microsoft 365 who need a no-cost, low-friction storage solution integrated with their existing ecosystem
🔵 Atlassian Confluence
✔ Advantages
Purpose-built for technical documentation — supports structured spaces, pages, and hierarchical knowledge bases
Rich editor with native support for code blocks, tables, macros, and inline diagrams (Draw.IO plugin available)
Seamless integration with Jira — links ERD documentation directly to issues, epics, and sprints
Full page version history with diff comparison between versions
Superior full-text search across all documentation content
✖ Disadvantages
Requires a separate Atlassian license — additional cost if not already part of the tech stack
Integration with Microsoft 365 requires additional configuration or third-party connectors
Higher onboarding effort for teams unfamiliar with Atlassian products
✦ Best for
Teams that already use Jira or need a robust, wiki-style knowledge base where documentation is a first-class deliverable
🏛️
Decision owner: Operations Team The final platform decision must be made by the Operations team based on existing licensing, infrastructure, and organizational workflows. Regardless of the platform chosen, the ERD HTML files must be stored in a dedicated folder or space named Technical Documentation / ERD, with access restricted to the development team and technical leads.
