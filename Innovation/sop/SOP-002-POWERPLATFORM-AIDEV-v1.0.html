Section 01

Purpose & Scope

This SOP defines the standard method for the Clara Fortuna team to design, build, modify, and deliver Power Platform solutions using AI assistance, reducing development time and enabling team members without deep Power Platform expertise to contribute meaningfully.

Why This Method

Traditional Power Platform development requires deep knowledge of Dataverse schema design, XML customization files, and ALM processes. This method uses Claude AI to handle the knowledge layer, the team provides the business context, Claude provides the technical specification, and Power Platform CLI handles the packaging and delivery.

The same method works for every component inside a Power Platform solution, not just model-driven apps. Once you understand the unpack/modify/repack cycle, you can improve any part of any solution.

🏗️
Model-Driven Apps
Tables, forms, views, dashboards, business process flows. Data-first enterprise apps.
🎨
Canvas Apps
Custom UI experiences. The .msapp file unpacks to JSON, fully readable by Claude.
⚡
Power Automate
Flows stored as JSON in the solution. Claude can add steps, change conditions, fix logic.
🌐
Web Resources
HTML, JS, CSS files embedded in the solution. Directly editable, no unpack needed.
🔒
Security Roles
Role definitions in XML. Claude can add or adjust permissions for specific tables.
📦
Deliver to Any Tenant
Export as managed .zip → import in client's tenant. No code access needed by client.
Business Impact: A solution built once in Clara Fortuna's Dev environment can be packaged and delivered to any utility client's tenant in under 10 minutes. The client receives a fully managed solution, they can use it but cannot accidentally break its structure.
Section 02

3 Maturity Levels

The method has three progressive levels. Start at Level 1. You will be productive immediately. Move to Level 2 once you've shipped at least one solution. Level 3 is the long-term automation goal.

Level 1 · Step 1

Design with Claude

Before touching Power Platform, use Claude to design the complete data model and app configuration. Claude's output becomes your build specification. Follow it exactly in the Maker Portal.

C

Client: [CLIENT NAME]
Sector: [e.g. Electric utility / Water utility / Gas distribution]
Business process: [DESCRIBE THE PROCESS IN 2-3 SENTENCES]

3. Form layout, for each table, list the sections and fields in order as they should appear on the main form

5. Security roles, define 2-3 roles with their access level per table (Read/Write/Create/Delete)

Format each section clearly. Use tables where helpful. Be specific. This output will be used directly to build the app.

Level 1 · Step 2

Build in the Maker Portal

Using Claude's output as your spec, build the solution in make.powerapps.com. Always work inside a Solution, never directly in the default environment.

1
Create a new Solution
Go to make.powerapps.com → select Clara Fortuna Dev environment → left menu → Solutions → New solution. Set Display name, Publisher: Clara Fortuna (prefix: cf_), and Version: 1.0.0.0. Click Create.
2
Create Dataverse tables
Inside your solution → New → Table. Follow Claude's table schema exactly: logical name, display name, primary column. For each table, add all columns Claude specified with their exact data types. Repeat for every table in the schema.
3
Create relationships
For each relationship in Claude's output: open the parent table → Relationships tab → Add relationship → select type (1:N or N:N) → select the related table. Use Claude's relationship names exactly.
4
Create the Model-Driven App
Inside solution → New → App → Model-driven app. In the app designer, add pages using Claude's sitemap structure. Configure forms and views per Claude's layout spec. Save and Publish.
5
Assign security roles
Settings → Security roles → create each role Claude defined. Set table permissions per Claude's access matrix. Assign roles to the app via the app's Properties panel.
Tip: If you get stuck on any step, paste the relevant part of Claude's output back into Claude and ask: "I'm on step [X] in make.powerapps.com. Based on this spec, what exactly should I click and configure?" Claude will guide you through the UI.

Level 1 · Step 4

Deliver to Client Tenant

Send the managed .zip to the client and walk them through the import, or import it directly if you have access to their tenant.

✓

They must have a Power Apps license. They select their target environment (their Production or Sandbox environment).
✓
Solutions → Import solution → Upload .zip
Client uploads the managed .zip file. Power Platform validates dependencies automatically. If there are missing dependencies, the portal shows them clearly.
✓

To modify an existing solution, adding fields, fixing flows, improving forms, changing canvas app logic, you unpack it into readable files, modify with Claude, and repack. This works on any solution regardless of how it was originally built.

Step-by-step unpack process

1
Export the unmanaged solution first
You can only meaningfully modify an unmanaged solution. If you only have a managed .zip, you need to export fresh from the source environment.

2
Unpack into a folder
Terminal
$ pac solution unpack --zipfile "./UnifiedCSRPortal.zip" --folder "./UnifiedCSRPortal-src" # You should see output like: # Unpacking solution components... # Done. Solution extracted to ./UnifiedCSRPortal-src
3
Open the folder in VS Code
File → Open Folder → select UnifiedCSRPortal-src. You will see the complete solution as structured files, ready for Claude to read and modify.

Level 2 · Step 8

Repack and Import

After saving Claude's modified XML back into the source folder, repack the solution and import it to test your changes.

1
Increment the version in Solution.xml
Open Other/Solution.xml. Find the <Version> tag and increment it (e.g. 1.2.0.9 → 1.2.1.0). This prevents import conflicts.
Other/Solution.xml: edit this line
<!-- Before --> <Version>1.2.0.9</Version> <!-- After --> <Version>1.2.1.0</Version>
2
Repack with PAC CLI
Terminal
$ pac solution pack --zipfile "./UnifiedCSRPortal-v1.2.1.0.zip" --folder "./UnifiedCSRPortal-src" # Expected output: # Packing solution components... # Done. Solution packed to ./UnifiedCSRPortal-v1.2.1.0.zip
3
Fix the Content_Types.xml (Critical, Known Issue)
After PAC packs the solution, open the resulting .zip and replace the [Content_Types].xml with the one from the original downloaded solution. This fixes an encoding mismatch that can prevent the app from being editable after import.
Do not skip this step. PAC marks XML files as text/xml but Power Platform expects application/octet-stream. Without this fix the imported solution may not be editable in the maker portal. Keep a copy of the original [Content_Types].xml from your first export for reuse.
4
Import to Dev for testing
Terminal: import to Dev
$ pac solution import --path "./UnifiedCSRPortal-v1.2.1.0.zip" --publish-changes # Or import via VS Code: right-click solution → Import Solution
✓
Verify in make.powerapps.com
Open Dev environment → Solutions → find your solution → open the app and verify the changes are visible. If something looks wrong, recheck the modified XML against Claude's output for any typos or mismatched tags.

Known Issues & Fixes

Issue 1: Solution not editable after import

Problem: PAC CLI sets XML content type to text/xml but Power Platform expects application/octet-stream in the [Content_Types].xml file.

Fix: After running pac solution pack, open the resulting .zip, replace [Content_Types].xml with the one from your original export. Save. Import the fixed zip.

Issue 2: Import fails with "Missing dependencies"

Problem: The target environment is missing a component that this solution depends on (e.g. a table from another solution, a connector).

Fix: The import portal lists exactly what is missing. Install or import the dependency first, then retry.

Issue 3: Claude modifies XML but import breaks the app

Problem: Claude introduced a tag inconsistency or wrong GUID reference in the XML.

Fix: Go back to Claude and paste the broken XML section. Ask: "This XML caused an import error. The error message is [X]. Find and fix the issue without changing anything else."

Issue 4: Changes visible in Dev but not in QA after import

Problem: The solution was imported but not published.

Fix: In make.powerapps.com → Solutions → open the solution → click Publish all customizations. Or add --publish-changes flag to the pac solution import command.

Section 09: Visual Enhancement

Web Resources: The Visual Layer

Model-driven apps are powerful but visually generic by default. Web resources are the mechanism to change that entirely. A web resource is any HTML, CSS, or JavaScript file registered in Dataverse and embedded inside a form, dashboard, or sitemap. With Claude writing the code, the team can produce enterprise-quality visual components without a frontend developer.

Key principle: Everything you see in this section is standard HTML, CSS, and JavaScript. Claude writes all of it. The team registers it in the solution. Power Platform renders it. No additional licenses or tools required beyond what Clara Fortuna already has.

3 Places to Embed a Web Resource

📋
On a Form
Embedded as a component inside any tab or section. Reads and writes field values from the current record. Best for dynamic visualizations tied to a specific record.
📊
On a Dashboard
Full-width panel alongside charts and grids. Reads Dataverse data via the Web API. Best for KPI tiles, summary cards, and custom charts across multiple records.
🗺️
In the Sitemap
Standalone page in the app navigation. Not connected to a specific record or form. Best for help pages, process guides, or embedded external tools.
Critical technical constraint (verified Microsoft Learn): The Xrm object is NOT directly available inside an HTML web resource. Use parent.Xrm.* when the web resource is embedded in a form container. For standalone web resources (dashboard or sitemap), use GetGlobalContext from ClientGlobalContext.js.aspx to access environment information, and the Dataverse Web API directly for data access.

Component Type 1: KPI Dashboard

A full-width HTML panel on a dashboard showing live metrics pulled from Dataverse. Uses Chart.js loaded from CDN for visualizations. Reads data via parent.Xrm.WebApi or direct Dataverse Web API calls.

How to Register a Web Resource in the Solution

1
Add the file to your solution
In make.powerapps.com, open your solution → New → More → Web Resource. Upload the HTML file Claude generated. Set the logical name using the convention cf_/webresources/[name].html. Display name is what appears in the portal.
2
Add to a form (for form-embedded components)
Open the table form in the form designer → add a new 1-column section in the target tab → click Components → Web Resource → select your web resource. Set the height in rows (1 row ≈ 24px, so 12 rows ≈ 288px). Save and Publish.
3
Add to a dashboard (for KPI panels)
In your app, open or create a dashboard → click Insert Web Resource → select your web resource. Set the column span and height. Save. The dashboard is now available in the app.
4
Add to the sitemap (for standalone pages)
In the app designer → sitemap editor → add a new Sub Area → set Type to Web Resource → select your web resource. It now appears as a navigation item in the left sidebar of the app.
5
Export and include in solution .zip
When you export the solution, web resources are automatically included. In the unpacked folder they appear under WebResources/ as plain HTML/CSS/JS files — directly editable with Claude without needing to re-register them.
