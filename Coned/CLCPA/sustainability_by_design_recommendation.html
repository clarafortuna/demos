02 Side-by-Side

Advantages and trade-offs.

MethodSymmetric presentation. Both options shown with their actual advantages and honest trade-offs.
Option A
Power Apps & Dataverse
Low-code · Microsoft Power Platform
Advantages
  • Build in progress. Working version already maturing.
  • Corporate IT supported today, no new platform to onboard.
  • Dataverse out of the box: relational model, row-level security, auditing.
  • Configured, not coded. Forms, approvals, workflows ship faster.
  • Native AI path via Power Automate and AI Builder.
  • Citizen-developer friendly. SMEs can contribute.
  • Modern UX by default. Responsive web and mobile.
  • Microsoft roadmap alignment: Copilot, agents, model integration.
Trade-offs
  • Dataverse storage quota (5 GB default). SQL connector is available for larger volumes.
  • Edge-case UI may require PCF component development.
  • Governance discipline (DLP policies, environment strategy) up front.
Option B
On-Premises C# Extension
Custom code · existing internal site
Advantages
  • Codebase familiarity on the existing team.
  • Full on-premises data residency.
  • Unlimited UI control. No framework constraints.
  • Consolidates into a site leadership already operates.
  • Existing database can hold all data regardless of volume.
Trade-offs
  • Starts from scratch. Existing Power Apps work set aside.
  • C# developer time required for every change.
  • Custom plumbing for auth, audit, access, workflow, notifications.
  • AI integration is a custom build.
  • Infrastructure obligations stay with the team.
  • Mobile / modern UX requires significant added work.
  • Tech debt compounds with site growth.

04 Assessment

Reading the comparison.

ReadingThe two options do not come out the same on the criteria most relevant to this application.

On-premises C# is a strong fit on five criteria: Corporate IT support, data residency, licensing posture, unbounded UI customization, and existing-database storage capacity.

Power Apps with Dataverse is a strong fit on eleven criteria, including everything C# is strong on except data residency and UI ceiling, plus the build already being in progress, faster time to first version, lower developer capacity requirement, native AI path, mobile-ready UX, reduced infrastructure ownership, maintenance load, and Microsoft roadmap alignment. Power Apps is already licensed at the organization, so licensing is not an exposure for either option.

On-premises C# would be the stronger choice only if data residency or unlimited UI control were hard requirements; on the information available, neither is. Dataverse's 5 GB storage default is not a hard limit either. The Power Apps SQL connector supports the existing SQL Server directly if larger data volumes or existing tables are in scope.

Summary. Power Apps is the better-fit platform for Sustainability by Design on the facts presented, and the CREATE process is already approved for this platform. On-premises C# remains a viable alternative with real strengths, particularly if data residency or deep UI customization become hard requirements.

If leadership proceeds on Power Apps, our team is available to support the work. We currently develop and administer the Unified CSR Portal, an enterprise-scale Power Platform application. This is offered as context for the decision, not as a basis for it.
