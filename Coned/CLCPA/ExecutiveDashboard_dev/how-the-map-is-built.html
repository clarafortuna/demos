DAC Map: How the Map Is Built

A walkthrough of how the “DAC Tracts” map is assembled and drawn, detailed enough to rebuild it from scratch or add a new layer. Companion to the Data Sources & Reproducibility page.

The Data Sources page answers where the data comes from. This page answers how the map is built and drawn: the Python pipeline that produces map_payload.json, the side build that produces the service_territories.geojson overlay, and the browser code (Leaflet) that turns those files into the interactive choropleth in the dashboard's Executive Summary. Everything below is grounded in the live code: the pipeline scripts in Data/ and the map module in app.js.

Part 1

Architecture at a glance

Five source datasets feed a four-step Python pipeline. The pipeline writes one file, map_payload.json, which the browser draws with Leaflet. A side script builds the service-territory overlay, which the map loads lazily on demand.

The map loads map_payload.json on first view (the tract choropleth) and lazily loads Data/service_territories.geojson only when a service-area layer is first toggled on. Geometry plus DAC scores, indicators, ConEd customer counts, neighborhood labels, and the per-tract network and gas overlaps are all baked into map_payload.json at build time, so the browser does no joins.

Part 2

Sources, in one line each

Full provenance (vintages, URLs, access, exact filenames) lives on the Data Sources & Reproducibility page. The pipeline below joins five sources, all keyed on the 11-digit GEOID and filtered to Con Edison's six counties (Bronx, Kings, New York, Queens, Richmond, Westchester):

  • GeometryU.S. Census tract polygons, 2020 cartographic boundaries with 2010 as a fallback for legacy GEOIDs (Data/ny_tracts.geojson, Data/ny_tracts_2010.geojson). Public.
  • DAC dataNYSERDA Disadvantaged Communities: designation, scores, and the indicator percentiles (Data/NYS_DAC.geojson). Public.
  • NeighborhoodsNYC Department of City Planning tract-to-NTA crosswalk (Data/2020_Census_Tracts_to_2020_NTAs_and_CDTAs_Equivalency_20260601.csv). Public.
  • ConEd customersPer-tract Electric and Gas accounts, EAP enrollment, and bill adjustment (Data/Electric.xlsx, Data/Gas.xlsx). Internal Con Edison data.
  • NetworksCECONY electric networks, CECONY gas service areas, and the Orange & Rockland (ORU) territory (shapefile sets in Data/Extra_info/). Internal Con Edison GIS.
Part 3

The build pipeline

map_payload.json is a GeoJSON FeatureCollection of 2,333 tract features plus a top-level nondac_by_county aggregate. It is produced in four idempotent steps; each re-derives its fields from the source files on every run. (A separate script, Data/build_payload.py, builds payload.json for the dashboard's section tables and charts; it is not part of the map pipeline.)

0

build_base_map_payload.py: base build

Joins census-tract geometry (2020, with 2010 fallback, recorded per feature in _geom_year), the NYSERDA DAC base scores, and the Con Edison Electric/Gas extracts on GEOID, restricted to the six counties. Rolls Non-DAC borough totals into nondac_by_county. The universe is every GEOID present in the Electric, Gas, or DAC data within those counties.

  • Inputs ny_tracts.geojson · ny_tracts_2010.geojson · NYS_DAC.geojson · Electric.xlsx · Gas.xlsx
  • Output map_payload.json: 2,333 features (1,059 DAC + 1,274 Non-DAC), about 20 base properties each, plus nondac_by_county
  • Base properties include GEOID, County, City_Town, DAC_Desig, Pop_Cnt, HH_Cnt, Comb_Sc, Rank_State, Burden_Pct, Vulner_Pct, Energy_Aff, the per-utility elec_dac/elec_accts/elec_eap/elec_adj and gas_dac/gas_accts/gas_eap/gas_adj, and _geom_year
1

enrich_map_payload.py: granular DAC indicators

Left-joins 48 fields from NYS_DAC.geojson onto each tract: the 44 indicator percentiles plus four secondary rankings/scores (Rank_NYC, Rank_ROS, Burden_Sc, Vulner_Sc). DAC tracts with a GEOID match copy the values; every other tract gets those 48 fields set to null, so the schema is uniform across all features.

  • Inputs NYS_DAC.geojson · map_payload.json
  • Output map_payload.json (overwritten, minified), about 68 properties per tract
2

enrich_neighborhoods.py: borough + neighborhood

Sets borough (display name from County: Kings to Brooklyn, New York to Manhattan, Richmond to Staten Island) and neighborhood (NYC tracts get the NTA name from the crosswalk; Westchester uses a cleaned City_Town; anything unmatched is null). Writes a one-time backup, map_payload.backup2.json.

  • Inputs 2020_Census_Tracts_to_2020_NTAs_and_CDTAs_Equivalency_20260601.csv · map_payload.json
  • Output map_payload.json (overwritten) · map_payload.backup2.json
3

enrich_electric_network.py: network / service-area fields

Adds electric_networks (CECONY networks from CECONY_Electric.shp, field NETWORK) and gas_areas (CECONY gas borough areas from CECONY_Gas.shp, field BORONAME) to every tract via polygon overlap: keep each area covering at least 5% of the tract, dominant first; if none reaches 5% but one intersects, keep the single largest; no intersection leaves an empty list. Overlap is computed in the shapefiles' native CRS, EPSG:2263 (NAD83 / NY Long Island, US ft). These values appear in the tract tooltip.

  • Inputs Data/Extra_info/CECONY_Electric.shp · Data/Extra_info/CECONY_Gas.shp · map_payload.json
  • Output map_payload.json (overwritten), about 72 properties per tract (adds electric_networks, gas_areas)

Run order

# from Coned/CLCPA/ExecutiveDashboard_dev/
python Data/build_base_map_payload.py # 0. base build (geometry + DAC + ConEd extracts)
python Data/enrich_map_payload.py   # 1. add 48 DAC indicator / score fields
python Data/enrich_neighborhoods.py  # 2. add borough + neighborhood
python Data/enrich_electric_network.py # 3. add electric_networks + gas_areas (tract / network overlap)

The overlay side build

_make_territories.py: build the service-area overlay

A one-off converter (not part of the four-step pipeline, and not a runtime dependency) that reprojects the same three Data/Extra_info/ shapefiles to WGS84 (EPSG:4326) and writes one file, Data/service_territories.geojson, tagging each feature with a layer property (electric, gas, or oru). It applies a proper datum transform per layer (NAD83 for CECONY; a NADCON grid transform for ORU's NAD27). Re-run it only when the source shapefiles change.

  • Inputs Data/Extra_info/CECONY_Electric.shp · CECONY_Gas.shp · ORU_Territory.shp
  • Output Data/service_territories.geojson (the committed runtime overlay, about 3.48 MB)

Reproducibility note (CLCPA-116)

The committed map_payload.json is the richer source of truth.
A clean run of the pipeline reproduces a functionally equivalent file, not a byte-identical one. Known differences in a from-scratch rebuild: City_Town (and therefore the Westchester neighborhood) is populated on Non-DAC tracts in the committed file but not by the current base build; the *_adj values round at a different decimal precision; and a small number of tracts differ in electric_networks near the 5% overlap threshold (geometry-library version sensitivity). Treat the committed file as authoritative for the dashboard, and the pipeline as the way to regenerate or extend it, confirming any rebuild against the committed values rather than assuming a byte-for-byte match.

Part 4

How the map is drawn (Leaflet, in app.js)

The map is a module inside app.js. Two functions drive it: renderDACMap() returns the panel HTML (title, the Borough / Neighborhood / Color-by controls, the legend, the Layers panel, and an empty map container), and the async mountDACMap() instantiates Leaflet into that container once it is in the DOM. The map uses Leaflet plus turf.js (to dissolve selected-neighborhood tracts into one outline); both load from a CDN in ExecutiveDashboard.html.

1. Load the tract data

getMapGeo() fetches the payload once and caches it in _mapGeoCache. When the app runs hosted on Dataverse it overlays the eight editable ConEd fields onto the features by GEOID; running standalone, the overlay is null and the file values are used as-is.

// app.js async function getMapGeo() { if (_mapGeoCache) return _mapGeoCache; const res = await fetch('./map_payload.json'); const geo = await res.json(); const overlay = await Storage.getMapOverlay(); // null unless hosted on Dataverse if (overlay) applyMapOverlay(geo, overlay); _mapGeoCache = geo; return _mapGeoCache; }

2. Create the base map and draw the tracts

mountDACMap() creates the Leaflet map (custom zoom control bottom-right, fractional zoom), adds a light CARTO basemap, then draws every tract as one GeoJSON layer. The fixed initial view centers the six counties.

const map = L.map(containerId, { zoomControl: false, attributionControl: false, zoomSnap: 0.1 }); L.tileLayer('https://{s}.basemaps.cartocdn.com/light_nolabels/{z}/{x}/{y}{r}.png', { maxZoom: 19 }).addTo(map); const geoLayer = L.geoJSON(geo, { style: styleFeature, onEachFeature: onEach }).addTo(map); map.setView([40.93, -73.9], 9.7);

3. Color tracts: DAC vs Non-DAC, by indicator

styleFeature() decides each tract's fill. A tract is DAC when DAC_Desig === 'Designated as DAC'. Non-DAC tracts are always a uniform gray (#a8a8a8); they are never colored by score. DAC tracts are colored by the currently selected indicator through colorForFeature(), and a DAC tract with missing data is the lightest blue (#d4e3f2), never gray. Two ramps exist: dacMapColor() for the Combined Burden Score (its own bins at 90, 100, 110, 120) and dacMapColorPct() for the 0 to 100 percentile indicators (bins at 20, 40, 60, 80). DAC tracts are filled at 0.78 opacity, Non-DAC at 0.55, and out-of-scope tracts are dimmed to 0.12.

function colorForFeature(props, isDAC) { const keys = _mapState.indicators; if (keys.length === 1) { const meta = mapIndicatorMeta(keys[0]); const raw = props ? props[meta.key] : null; return meta.scale === 'score' ? dacMapColor(raw, isDAC) : dacMapColorPct(raw, isDAC); } return dacMapColorPct(tractMean(props, keys), isDAC); // average of several percentile indicators }

4. The "Color by" indicator dropdown

The indicator picker is a custom grouped multi-select built by mapDropdownHtml() (a native <select> is avoided so the open list can be fully styled). Options come from MAP_INDICATOR_GROUPS (Summary, Environmental Burdens, Climate Risks, Health, Demographics / Vulnerability, Affordability & Ranking). The current selection lives in _mapState.indicators (default ['Comb_Sc']). One selection uses that indicator's own scale; selecting several averages their percentiles. Changing the selection recolors the geoLayer and rebuilds the legend (mapLegendHtml()) and title (mapTitleText()).

5. Tooltips on hover

onEach() wires each tract's mouseover to highlight it and fill a floating tooltip from the feature properties: borough (borough or boroughLabel(County)), DAC_Desig, neighborhood, and for DAC tracts Comb_Sc, Rank_State, and Pop_Cnt. A helper, utilityBlock(), renders the Electric and Gas figures from elec_accts/elec_eap and gas_accts/gas_eap; when both are absent it shows "Outside ConEd ... service area."

utilityBlock('Electric', p.elec_accts, p.elec_eap) utilityBlock('Gas', p.gas_accts, p.gas_eap)

6. Borough and neighborhood filters

The Borough dropdown (built in renderDACMap()) maps display names to county values (Brooklyn to Kings, Manhattan to New York, Staten Island to Richmond, plus Bronx, Queens, Westchester, and "All boroughs"). Choosing one sets _mapState.county; styleFeature() then dims tracts outside it. The Neighborhood dropdown is rebuilt per borough by rebuildNeighborhoodDropdown() and stored in _mapState.neighborhoods; selected neighborhoods are outlined (dissolved with turf.js when available). "Clear all" resets both filters.

7. The Layers panel and the lazy service-area overlay

The Layers panel offers five toggles: DAC criteria (the tract choropleth itself, on by default), Electric networks, Gas service area, ORU territory, and EAP enrollment (a separate heatmap driven by the payload, not the overlay file). The three service-area toggles are backed by Data/service_territories.geojson, fetched lazily by ensureTerritoryGeo() on the first toggle and cached in _territoryGeoCache. setTerritory(kind, on) filters that file by the feature's layer property and draws a non-interactive styled layer (so tract hover and click still work underneath); selecting ORU flies the map out to its bounds.

function ensureTerritoryGeo() { if (_territoryGeoCache) return Promise.resolve(_territoryGeoCache); if (!_territoryFetchPromise) { _territoryFetchPromise = fetch('./Data/service_territories.geojson') .then(r => r.ok ? r.json() : Promise.reject(new Error('service_territories.geojson ' + r.status))) .then(j => (_territoryGeoCache = j)); } return _territoryFetchPromise; } // drawn per kind: electric (amber), gas (green), oru (purple) const feats = _territoryGeoCache.features.filter(f => f.properties.layer === kind); L.geoJSON({ type: 'FeatureCollection', features: feats }, { interactive: false, style: TERR_STYLE[kind] }).addTo(map);

Overlay location note (CLCPA-101)

The overlay's runtime path is provisional.
service_territories.geojson currently lives in Data/, alongside the build inputs and scripts, and the map fetches it from ./Data/service_territories.geojson at runtime. That folder is otherwise build-time only, so its placement as a runtime asset is provisional: if runtime assets are later moved to a dedicated location, both the file path and the fetch() in ensureTerritoryGeo() must move together. As of this writing the location is unchanged.
Part 5

Recipe: adding a new layer

A. A new choropleth indicator (color tracts by a new field)

  • 1 Get the field into map_payload.json: if it comes from the DAC dataset, it likely already arrives via enrich_map_payload.py; otherwise add it in the relevant pipeline step, then re-run the pipeline.
  • 2 Add one entry to MAP_INDICATOR_GROUPS in app.js: { key: 'YourField', label: 'Your label', scale: 'pct' } (use 'score' only for a Combined-Burden-style raw bin).
  • 3 Nothing else: the dropdown, colorForFeature(), the legend, and multi-select averaging all read from that catalog automatically.
  • Note percentile fields share the 0 to 100 ramp; only a 'score'-scale field needs its own bins (see dacMapColor()).

B. A new service-area overlay (like the network layers)

  • 1 Drop the shapefile set into Data/Extra_info/ and add it to the LAYERS list in _make_territories.py (basename, a layer tag, the name field), then re-run it to regenerate service_territories.geojson.
  • 2 Add a style for the new tag to TERR_STYLE in mountDACMap().
  • 3 Add a toggle to the Layers panel in renderDACMap(): <input type="checkbox" data-layer="yourtag">. The existing change handler routes any non-special tag through setTerritory(), which filters by layer and draws it, so no new wiring is needed for a standard overlay.
  • Note if the new field should also appear in the tract tooltip (like electric_networks), add a per-tract overlap step modeled on enrich_electric_network.py so the value is baked into map_payload.json.
