Data Sources

The datasets behind the DAC map: where each one comes from, what it brings, and how to update it when a newer version is published. Click a source to see its update steps.

Two rules whenever you update any source. Keep the join key intact: every tabular source matches the map on the 11-digit GEOID, so a new file must carry the same GEOID (and the same column names the build expects). And re-run the build step that reads it, so the change flows into map_payload.json. The one exception is the Con Edison customer data, which updates through a file upload instead of a rebuild.

1   Census tract geometry

rarely changes
From
U.S. Census Bureau (TIGER/Line tract boundaries), saved as GeoJSON
Files
ny_tracts.geojson (2020, primary) and ny_tracts_2010.geojson (2010, fallback)
Brings
the polygon shape of every area on the map, and the GEOID that all other sources join on
How to update

The 2010 file is a fallback only: it supplies a boundary for tracts missing from the 2020 file. The exact tracts that fall back are available as a separate export.

  1. Tract boundaries change only rarely (each decennial census, or an occasional vintage correction).
  2. When a newer vintage is published, export the New York tracts for the six counties as GeoJSON, keeping the GEOID property.
  3. Replace ny_tracts.geojson (same filename, same GEOID field). Only touch the 2010 fallback if you need older-vintage coverage.
  4. Re-run the base build. A new vintage can add or drop tracts, so re-check the feature count afterward.

2   NYSERDA DAC dataset

updated when republished
From
NYSERDA / New York State Climate Justice Working Group (the CLCPA Disadvantaged Communities data)
File
NYS_DAC.geojson
Brings
the DAC / Non-DAC designation, the headline fields (population, households, combined score, ranks, burden, vulnerability, affordability), and the 48 granular indicator percentiles and scores
How to update
  1. NYSERDA revisits the designations periodically. When a new release is published, download it as GeoJSON keyed by GEOID.
  2. Replace NYS_DAC.geojson.
  3. Re-run the base build and the indicator step so both the headline fields and the 48 indicators refresh.
  4. If NYSERDA renames any columns, the field lists in the build need a matching update.

3   Con Edison customer extracts

editable each cycle
From
Con Edison internal account and billing systems
Files
Electric.xlsx and Gas.xlsx (the Export sheet)
Brings
per area: total accounts, accounts in the Energy Affordability Program, bill adjustments, and the DAC class
How to update
  1. This is the routine update, done each reporting cycle, and the source you own.
  2. Export fresh per-area figures with GEOID in the first column and the same headers: DAC Indicator, Total Accts, Total EAP Accts, Total Adjustment.
  3. Send the refreshed files to the maintainer. There is no upload for spreadsheets: these figures reach the dashboard only by rebuilding map_payload.json through the payload pipeline and redeploying it. That procedure is being validated and is not self-service yet.

4   NYC neighborhood crosswalk

updated when republished
From
NYC Department of City Planning (the Census-tracts-to-NTAs equivalency table)
File
2020_Census_Tracts_to_2020_NTAs_and_CDTAs_Equivalency_*.csv
Brings
the neighborhood (NTA) name for each New York City area
How to update
  1. When City Planning publishes a new equivalency (revised NTA names or boundaries), download the new CSV.
  2. It must keep the GEOID and NTAName columns (UTF-8).
  3. Replace the file and re-run the neighborhood step. If the filename changes, update the reference to it in the build.

5   Service-territory shapefiles

updated when boundaries change
From
Con Edison (CECONY electric and gas) and Orange & Rockland (ORU)
Files
Data/Extra_info/CECONY_Electric.shp, CECONY_Gas.shp, ORU_Territory.shp (each with its .prj and .dbf)
Brings
the utility service-area boundaries (the drawable overlay) and the per-area network and gas-area tags
How to update
  1. When the utility boundaries change, get the new shapefile set from the utility.
  2. Replace the files, keeping each .shp together with its .dbf and .prj, and keeping the name fields (NETWORK, BORONAME, STATE).
  3. Re-run the network step (per-area tags) and rebuild the overlay file.
  4. Mind the projection: the Con Edison files are in EPSG:2263, the ORU file is in NAD27.
