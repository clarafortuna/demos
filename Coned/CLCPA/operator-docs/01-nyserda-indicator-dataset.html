NYSERDA indicators — building and uploading a dataset version

How a new NYSERDA Disadvantaged Communities release becomes the data the map, the tooltips, the tract detail panel and the CSV export all read.

Before you start

Three things that decide whether this goes smoothly.

Where you run these commands

Everything in this guide runs from the folder that contains the Data/ folder, invoking scripts as python Data/<script>.py. The scripts resolve their own paths, so running them from inside Data/ will fail on missing inputs.

What you need installed

This guide needs Python only — no additional packages. The converter uses the Python standard library. (The geometry builder in guide 2 does need extra packages; this one does not.)

One file in Data/ decides what the indicators are called

Data/indicator_catalog.json holds the six indicator groups and the fifty indicators inside them — their keys, their labels, and whether each is a percentage or a score. The converter reads it to build the dataset’s own description of itself, which is what lets the dashboard’s Color by list, tooltips and CSV export rebuild themselves from an upload rather than from a code change.

You do not normally touch it. It matters in one situation: if a future NYSERDA release adds, renames or removes an indicator, that file is where the change goes — see the NOTE: paragraph in step 3.

It records which dashboard build it was taken from, by checksum, so a dataset built with it can always be traced back.

Step 1 — Download the NYSERDA release

Source: the New York Department of State Geographic Information Gateway.

https://opdgig.dos.ny.gov/datasets/2579112b69b04b4c9a09f4cf013983dc

Export it as GeoJSON and save it as Data/NYS_DAC.geojson, with exactly that filename.

What the file containsWhy it matters
1,736 features, statewide The six Con Edison counties are a subset. The converter narrows it for you.
Designated DAC tracts only There are no Non-DAC rows in this file at all. The converter builds the Non-DAC roster itself, which is why the output has more tracts than the input.

The DAC criteria were finalised by the New York State Climate Justice Working Group on 2023-03-27. That date is what you pass as --raw-date below.

Step 2 — Convert it

python Data/convert_nyserda_raw.py --version 1.0 --geoid-vintage 2010 --raw-date 2023-03-27
ArgumentNotes
--versionrequired The version label, e.g. 1.0. It also names the output file.
--geoid-vintagerequired 2010 or 2020 only. Anything else is rejected. See “Which vintage” below.
--raw-datealways pass it YYYY-MM-DD. Written into the stored source label. If you omit it, the script falls back to the file’s modification date and says so — but that is the date you downloaded it, not the date the data was published.
--raw PATHoptional Default Data/NYS_DAC.geojson.
--universe PATHoptional Default Data/out/tract_geometry_pure-<vintage>.json — the tract geometry from guide 2. It defines which tracts exist.
--source-label TEXToptional Replaces the generated label. Still capped at 254 characters.
--verify-against FILEoptional Compares what it just built against an existing dataset file.
--no-writeoptional Build and check without writing anything. Useful for a dry run.
Which vintage?

The vintage must match the tract geometry the map is drawing. Today that is 2010. If you pass 2020, the dashboard will refuse the dataset unless matching 2020 geometry is published — see “If the dashboard refuses it” below.

The two middle lines are the extras report

  • discarded — three artefacts the export tool adds. Dropped on purpose; nothing to do.
  • carried by raw, not by the dataset — five real NYSERDA columns the dashboard does not use. Also expected.
A paragraph beginning NOTE: is a decision, not a warning to skim past.

If a future NYSERDA release adds or removes a column, the script prints a NOTE: saying the column list no longer matches what was recorded when the script was written.

Somebody has to decide whether the dashboard should carry the new column. The converter cannot make that call. Do not treat it as noise; raise it before uploading.

Where the file lands

Data/out/nyserda_dac_v<version>.json, with dots replaced by underscores. So --version 1.0 produces Data/out/nyserda_dac_v1_0.json.

One number that will otherwise look like a fault

A fresh run produces 1,181,466 bytes. The v1.0 file currently stored in the dashboard is 1,181,337 bytes. The 129-byte difference is entirely the longer source label (228 characters against 99). Every tract value is identical. Comparing file sizes and concluding something broke is the expected wrong turn here.

Step 4 — Upload it

  1. Open the dashboard and go to Map Layers.
  2. Under Upload data file, choose your nyserda_dac_v1_0.json. The file itself says what kind of dataset it is; you do not choose a type.
  3. Read the Validated panel. It shows the tract count, the field count, the version and the vintage. Anything in a Heads up block is worth reading before continuing.
  4. Press Upload version.
  5. The new version arrives inactive. Nothing on the map has changed yet.
  6. When you are ready, switch it to Active in the Tract datasets list. The checks run again at this point, against the map as it is drawn right now.
Activating is deliberately a separate decision

Uploading stores a version. Activating makes it what everybody sees. Activating one version automatically switches off the previous one — there is never more than one live indicator dataset.

The previous version stays stored and is how you go back.

If the dashboard refuses it

Refusals are specific. The message names the reason; these are the ones you are most likely to meet.

MessageWhat it means
…coverage below the floor… The dataset’s tracts do not match the tracts being drawn. Almost always a vintage mismatch: a 2020-keyed dataset against 2010 geometry matches about 93.6% and is refused. Rebuild with the matching --geoid-vintage, or publish the matching geometry first (guide 2).
record FieldCount (…) disagrees with the file The stored record and the uploaded file describe different things. This normally means a value was typed by hand and does not match what the script printed.
this file declares kind … which this build does not recognise The file is a kind this version of the dashboard does not know. Usually a file built by a newer script than the deployed dashboard.

A refusal never damages anything. The previously active version keeps running and the map keeps drawing.

What this flow does not involve

The Con Edison spreadsheets are not part of this.

Electric.xlsx and Gas.xlsx play no role in building a NYSERDA indicator dataset. An earlier internal description of the pipeline said otherwise; it was wrong, and this is the correction.

Those two files supply the per-tract electric and gas account figures, and they travel a completely separate route described in guide 3. Nothing you do in this guide changes them, and nothing you do in guide 3 changes the NYSERDA indicators.

There is no upload for spreadsheets anywhere in the dashboard.

The file picker accepts .json and .geojson files only. A spreadsheet cannot be uploaded to the dashboard directly — it has to be converted by a script first. That is true in every one of these three guides.

The four kinds of data file, so you know where you are

All four upload through the same picker and are told apart by the file itself.

KindWhat it carriesGuideGoes live by
NYSERDA indicatorsThe ~56 per-tract indicator valuesThis one You switching it to Active
Tract geometryThe tract shapes and 8 map propertiesGuide 2 Matching the active dataset’s vintage
Service territoriesThe electric, gas and ORU outlinesGuide 2 Being the published overlay
Electric & gas figuresAccounts, EAP accounts, adjustmentsGuide 3 Matching the active dataset’s vintage

Only the first is switched on and off by hand. The other three are picked automatically once published, which is why they have no Active toggle.
