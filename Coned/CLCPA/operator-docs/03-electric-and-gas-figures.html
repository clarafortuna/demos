Electric and gas figures

How the account counts, energy-affordability enrolment and adjustment figures in the two Con Edison extracts reach the dashboard.

The one thing to know first

There is no upload for spreadsheets. The dashboard cannot read one.

The file picker in the dashboard accepts .json and .geojson files only. A spreadsheet cannot be uploaded to the dashboard, dropped onto it, or read by it in any other way.

The cycle is always: run a script to convert, then upload what the script produced. This is a deliberate design decision, not a missing feature, and it is not going to change.

So the whole cycle looks like this:

  the two Con Edison extracts
             |
             |   build_coned_dataset.py          (a script, on your machine)
             v
  coned_operational_v1_0-2010.json               (this is what the dashboard takes)

Step 1 — Put the extracts in place

Two files, saved with exactly these names:

Data/Electric.xlsx
Data/Gas.xlsx

Each must contain a sheet named Export with these columns. Column order does not matter; the names do.

ColumnWhat it is
Geo IDThe 11-character census tract identifier. Must be the first column.
DAC IndicatorDAC or Non-DAC.
Total AcctsAccount count for the tract.
Total EAP AcctsEnergy Affordability Program enrolment.
Total AdjustmentThe adjustment figure. Carries many decimal places; see below.
Leave the filter description at the bottom alone

Both extracts end with a row whose first cell is a description of the query that produced them — Applied filters: SVC_TYPE_CD is E / Year is 2025 / .... That is normal, and the converter drops it deliberately and tells you it did.

You do not need to delete it, and deleting other rows to “tidy up” the file is more likely to cause a problem than solve one.

Step 2 — Build the geometry first, if you have not

The converter takes its list of tracts from the tract geometry dataset for the vintage you are building. If that file is not there, it stops and says so.

REFUSED: no geometry dataset at Data/out/tract_geometry_pure-2010.json.
  The tract universe comes from the geometry that is drawn, not from
  map_payload.json, so this dataset does not depend on the file it
  exists to replace. Build it with update_map_data.py --vintage 2010.

Guide 2 covers that command. If the geometry is already built, skip this step.

Step 3 — Convert

python build_coned_dataset.py --vintage 2010
OptionWhat it does
--vintage 2010|2020defaults to 2010 Which tract vintage to build for. Must match a geometry dataset you have already built.
--forceas needed Permits overwriting an output file that already exists in Data/out/. Nothing else.

Requires Python and the openpyxl package:

pip install openpyxl

Reading that output

  • Not every tract has figures, and that is correct. 2,283 of 2,333 tracts have electric data; only 1,036 have gas. The rest are blank because the extracts have no row for them.
  • The dropped list is not an error list. It names the filter footer from each file, and any tract outside the vintage’s universe.
  • Four Putnam County tracts appear in the electric extract but are outside the Con Edison six-county area, so they are excluded and named.
Building for 2020 drops considerably more — and that is expected

The 2020 tract universe is 2,183 tracts, and 219 tract identifiers that carry electric data under 2010 numbering do not exist in 2020 at all. The 2020 build reports them as outside the universe.

This is the census renumbering between the two vintages, not a data fault. It is also why the two builds produce separate files rather than one.

Where the file lands

Data/out/coned_operational_v1_0-2010.json     176,215 bytes
Data/out/coned_operational_v1_0-2020.json     164,933 bytes

The version label carries the vintage — 1.0-2010, 1.0-2020 — because the two cover different tract lists and are not interchangeable.

Step 4 — Upload

  1. Dashboard → Map Layers → Upload data file → choose coned_operational_v1_0-2010.json.
  2. The Validated panel shows the tract count and the per-field counts. Check them against what the converter printed.
  3. Read the Heads up block. One of its notes always appears and is the important one — see the next section.
  4. Press Upload version. It publishes immediately; there is no separate activation step.

It appears afterwards on the Electric & gas figures card. The version whose vintage matches the live NYSERDA dataset is marked in use; others are available.

Uploading a new version retires the previous one for that vintage

The retired version stays stored and re-uploading it is how you go back. Uploading a 2010 version does not affect a published 2020 version, and the reverse.

How these figures combine with manual corrections

The most important behaviour in this guide, and the least visible.

The dashboard has a separate store of per-tract electric and gas values that can be corrected by hand. Both that store and this dataset supply the same eight fields, so the order matters:

Manual corrections — applied last, so they win
Electric & gas figures dataset — what the extracts say

In plain terms:

  • If a tract has been corrected by hand, the correction stays. Uploading a new dataset does not overwrite it.
  • If a tract has not been corrected, it shows the dataset value.
  • A blank correction does not erase the dataset value beneath it.
Corrected adjustment values will show fewer decimal places. That is correct.

The dataset carries the adjustment figures at full precision — fourteen or fifteen decimal places, exactly as the extract supplies them. The corrections store keeps four.

So a corrected tract legitimately shows a shorter number than an uncorrected one. It is not a rounding fault, and it is not a sign that the upload went wrong.

Today, no tract has been corrected

At the time of writing the corrections store holds a copy of the extract figures rather than any actual corrections. Until that changes, uploading this dataset produces no visible change on the map — which is expected, and was verified before release.

What it does give you is a record of where the figures came from: a version, a source label, and a fingerprint of the two extracts. That did not exist before.

When you need to do this

SituationRebuild these figures?
Con Edison sends new Electric.xlsx / Gas.xlsx Yes. This is the only trigger.
eGIS sends new network shapefiles No. Those change the boundaries and the tooltip network names — guide 2 — not the account figures.
A new NYSERDA release No. Different data entirely — guide 1.
You publish geometry for a vintage you had not used before Yes, build these figures for that vintage too, or tracts will show no electric or gas values.
The fingerprint is of the spreadsheets, not the shapefiles

This dataset records a fingerprint of Electric.xlsx and Gas.xlsx. The geometry and territory files record a fingerprint of the shapefiles. They answer different questions and are never compared to each other — the file says which is which, so nothing can confuse them.

If something goes wrong

MessageWhat to do
REFUSED: no geometry dataset at … Build the geometry for that vintage first — guide 2.
REFUSED: … already exists. Pass --force to overwrite it. The output is already there. Re-run with --force if you meant to replace it.
this file is missing N of the eight ConEd fields A column is missing from one of the extracts, or its header was renamed. Check the sheet against the column table above.
N column(s) do not align to the … GEOIDs The file was edited after it was built. Rebuild it rather than repairing it.
record TractCount … disagrees with the file The stored record and the file describe different things. Rebuild and re-upload rather than editing the record.

None of these damage anything. A refused upload changes nothing, and a refused dataset leaves whatever was there before still working.
