Tract geometry and service territories

One command builds both. This guide covers the command, what each of its options really does, and the procedure to follow when eGIS sends new shapefiles.

Start here: one command, not several

python Data/update_map_data.py --vintage 2010

This is the entry point. It checks what is on disk, downloads what is missing, converts it, rebuilds the service territory overlay when that is needed, and then runs the geometry builder. You do not run the individual scripts yourself.

If you have seen an older instruction naming a different script

The builder underneath is build_pure_geometry_dataset.py.

A file called build_geometry_dataset.py also exists. It is the older version, it produces 9 properties instead of 8, and it is kept only as a fallback. Running it by hand produces a file the dashboard will refuse on the field-count check. If an instruction names it, that instruction is out of date.

What you need installed

pip install pyshp pyproj shapely

Verified on Python 3.14.5 with pyshp 3.0.9, pyproj 3.7.2, shapely 2.1.2. Run from the folder that contains Data/.

The options, and what each one is for

OptionWhat it does
--vintage 2010|2020required Which tract vintage to build. There is no default — the command refuses to guess.
--forceas needed Only permits overwriting a dataset file that already exists in Data/out/. It does not skip checks and it does not override anything else.
--dry-runrecommended first Prints the preflight table and stops. No downloads, no writes. Run this first every time.
--refresh-territoriesas needed Rebuilds the territory overlay even when it already agrees with the shapefiles. It is rebuilt automatically when it is missing or disagrees; this forces it otherwise.
--refetchrare Re-downloads inputs that are already present. Use when you suspect a stale or truncated download.
--no-fetchrare Builds from what is on disk and opens no network connection.
--artifactoptional Also writes the 2010 change document. Applies to the 2010 build only.
--census-url URLrare Overrides where the Census boundary file is fetched from.
--crosswalk-id IDrare Overrides the NYC Open Data dataset used for the neighbourhood crosswalk.
--refresh-territories and --no-fetch cannot be combined

The command refuses the pair rather than half-working. Rebuilding the territory overlay requires the network: the ORU layer is in an older coordinate system and converting it correctly needs a transformation grid downloaded at the time. The geometry build itself is offline; the territory rebuild is not.

cr2bf_FieldCount is 8. This is worth checking twice.

The dashboard compares the stored record against the uploaded file and refuses the whole dataset if they disagree:

record FieldCount (9) disagrees with the file (8).

For geometry a refusal means the map has no shapes for that vintage. A record left at 9 from an older upload is the most likely way this goes wrong.

For 2020 the numbers differ: 2,183 tracts, 1,284,965 bytes, version label pure-2020.

The neighbourhood crosswalks

Two files from NYC Open Data, one per vintage.

VintageNYC Open Data datasetTitle
20108ius-dhrr 2010 Census Tract to Neighborhood Tabulation Area Equivalency table
2020hm78-6dwm 2020 Census Tracts to 2020 NTAs and CDTAs Equivalency

The 2020 identifier was previously unrecorded. It is hm78-6dwm.

Filenames are matched by prefix, not exactly

The command looks for a file beginning 2010_Census_Tract or 2020_Census_Tract, so a fresh export keeps whatever date suffix the portal gives it. You do not have to rename it to match an old filename.

Two matching files is an error, on purpose

If you leave both an old and a new export in the folder, the command stops and names both rather than silently picking one. Remove the old one.

Do not tidy up the CSV before using it. Use it exactly as downloaded.

The 2010 file has no GEOID column, so the builder constructs the key itself from the county and tract columns, stripping thousands separators and padding as it goes. All of that happens inside the builder. Pre-formatting the spreadsheet will break the key and is never required.

Service territories — why they are built by the same command

The two Con Edison shapefiles feed two different outputs:

  • the per-tract electric_networks and gas_areas values inside the geometry dataset — what the tooltip shows;
  • the service territory overlay — the orange, green and purple outlines the map draws.

Rebuild one without the other and the outlines on screen disagree with the numbers in the tooltip, with nothing on screen to say so. That is why one command now produces both, and why they are stamped.

The stamp

Both outputs record a fingerprint of the shapefiles they were built from. The command compares them and behaves differently depending on what it finds:

SituationWhat happens
The overlay is missingA note. It is rebuilt.
The overlay has no stampA warning. It predates stamping, so it cannot be checked either way — the build continues.
The stamps disagree The run stops, prints both fingerprints, and names the command that fixes it.

The ORU layer is deliberately excluded from the fingerprint: it feeds only the overlay, so including it would report a disagreement when nothing shared had changed.

The dashboard checks the same thing again, in the browser

The first time somebody switches on a territory layer, the dashboard compares the overlay’s stamp against the tract geometry it is drawing.

If they match, it draws and says so in the browser console. If they disagree, it refuses to draw, switches the checkbox back off, and shows a message — rather than showing outlines that do not match the numbers. If either side has no stamp, it draws and reports that it could not verify.

When eGIS sends new shapefiles

The full procedure. Follow it in order; the order is the part that matters.

  1. Replace the files. Put the new CECONY_Electric and CECONY_Gas files into Data/Extra_info/, replacing the old ones. Each needs all four parts — .shp, .shx, .dbf, .prj. A missing .prj means the coordinate system is unknown and the build stops.
  2. Look before you build. 
    python Data/update_map_data.py --vintage 2010 --dry-run
    The territory overlay row should read WILL REBUILD, because the stamp no longer matches the new shapefiles. If it says PRESENT, the new files did not land where you think they did.
  3. Build both vintages. The shapefiles are shared by both, so both are now out of date. 
    python Data/update_map_data.py --vintage 2010 --refresh-territories --force
python Data/update_map_data.py --vintage 2020 --force
    Only the first needs --refresh-territories — the overlay is not per-vintage, so rebuilding it once is enough.
  4. Upload 2020 geometry first, then 2010. 2010 is the vintage currently paired with the live dataset, so it is the one that can visibly break. Doing 2020 first proves the file and the record values before you touch the live pairing.
  5. Upload the territory overlay (Data/service_territories.geojson). It publishes immediately and retires the previous overlay; there is no separate activation step.
  6. Check it in the browser. Reload the dashboard, switch on Electric networks, and confirm the outlines draw. If they do not, the stamps disagree — which means one of the two uploads did not happen.
Do the geometry and the overlay in the same sitting

Between the two uploads the stamps disagree, and during that window the dashboard will refuse to draw the outlines. That is the safety check doing its job, not a fault — but it is visible to anyone using the dashboard, so keep the window short.

What this does not change

New shapefiles do not affect the electric and gas account figures. Those come from the Con Edison spreadsheets on a separate cycle — guide 3. You do not need to rebuild them when eGIS sends new boundaries.

Uploading, and what happens after

  1. Dashboard → Map Layers → Upload data file.
  2. Choose the built file. The file states its own kind; you do not pick one.
  3. Check the Validated panel against what the builder printed — particularly the tract count and the field count.
  4. Press Upload version.

Geometry and territories are published on upload. There is no Active toggle, because there is nothing to choose: the dashboard picks the geometry whose vintage matches the live dataset, and there is only ever one published territory overlay.

The previous version is retired, not deleted

Uploading a new set retires the one it replaces — and only after the new file has been uploaded and verified, so a failed upload can never leave a vintage with no geometry at all.

Retired sets disappear from the card but stay stored. Re-uploading one is how you go back.

What travels with these scripts

To run this on another machine you need, alongside the scripts:

  • Data/ny_tracts.geojson and Data/ny_tracts_2010.geojson — or let the command download and convert them for you;
  • both neighbourhood crosswalk CSVs;
  • Data/Extra_info/ with all four parts of each shapefile;
  • map_payload.json, in the folder above Data/;
  • a Data/out/ folder that exists or can be created.
Two of those files are Con Edison internal data

map_payload.json and the CECONY_* shapefiles contain per-tract customer account counts, energy affordability enrolment, and network geometry. Anyone assembling this package is handling Con Edison data. Appropriate within Con Edison; not appropriate anywhere else.
